Checking

How we check services

Every minute

All three checks run on a one-minute schedule. If the page cannot load the latest status record, or the record is more than 3 minutes old, the page shows the current status as unknown.

  • Primary server. Checks the primary service’s reported availability for the website and public APIs. The 3-minute limit applies to the observation.
  • Data server. Checks that a small database query returns the expected result and that a completed publication is available. The health response must be less than 5 minutes old. Publication readiness requires at least one completed batch and at least one published row, a catalogue measurement at most 75 seconds old, and a latest completed batch at most 24 hours old.
  • Failover service. Checks that saved network and archive data is available, Explorer reports ready, and both saved snapshots have capture timestamps. Snapshot age is shown for reference.

A valid health response can report stale data. “Last checked” is when monitoring recorded the result. The failover data times below show when the saved snapshots were captured.
